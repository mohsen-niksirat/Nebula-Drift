### 2. GitHub Actions workflow: .github/workflows/deploy.yml

A workflow that on every push to `main`:
1. Checks out the repo.
2. Installs Godot (pin an exact version — use 4.3 or 4.4 stable,
   whatever the export preset targets; be consistent).
   Use the standard community action `firebelly/godot-export` is
   outdated — prefer the well-maintained approach: download the
   official headless Godot Linux server binary from
   github.com/godotengine/godot-builds (or tuxfamily/GitHub release)
   and run `godot --headless --import` then
   `godot --headless --export-release "Web" build/web/index.html`.
   Download the matching **export templates** for that exact version
   (tpz from godotengine releases) and install them headlessly with
   `godot --headless --install-templates <file.tpz>`.
3. Exports to build/web/.
4. Uploads the Pages artifact and deploys with the official
   `actions/upload-pages-artifact` + `actions/deploy-pages` actions
   (permissions: pages: write, id-token: write; concurrency: pages).
5. Keep the workflow minimal and readable; no caching tricks needed
   initially except Godot binary/template caching if trivial.

IMPORTANT gotchas to handle:
- Godot headless needs `--import` (or `--editor --quit`) once before
  exporting so .godot/ import cache is generated — otherwise export
  fails with missing imported resources.
- The export must be non-interactive: any prompt = build failure.
- If the export prints errors, the workflow must FAIL (exit code),
  not deploy a broken build.
