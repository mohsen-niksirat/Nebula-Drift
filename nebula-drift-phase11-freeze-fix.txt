# Nebula Drift — Phase 1.1 Freeze Fix Prompt

Create a production-quality Godot 4.x / GDScript repair pass for the current repository.

## Current report

The exported Web build successfully shows the game, score, HP, level, XP, enemies, and bullets. However, during level-up the player reports that the game appears frozen:

- Player sees HUD update to `LV 2`
- Enemies stop moving because `GameManager.State.UPGRADE_PICK` pauses the tree
- The upgrade panel is partially off-screen and the upgrade cards are difficult or impossible to interact with
- WASD movement does not appear to work while paused

This is intentional pause behavior, but the UI is not clearly usable. Fix the upgrade selection UX and confirm movement input.

## Required behavior

1. When `RunState.gain_xp()` triggers `EventBus.level_up`, the UpgradePicker must:
   - appear centered inside the visible viewport
   - remain visible above gameplay
   - remain processable while `get_tree().paused == true`
   - clearly show three upgrade cards
   - allow mouse click selection
   - return the game to `SECTOR` after selection

2. Player controls:
   - use `Input.get_vector("move_left", "move_right", "move_up", "move_down")`
   - support WASD and arrow keys
   - use `Input.is_action_pressed("shoot")` for Space / left mouse
   - clamp the player inside the 1280x720 viewport
   - do not try to move during `UPGRADE_PICK`; paused movement is expected

3. UI:
   - UpgradePicker and HUD must use `process_mode = PROCESS_MODE_ALWAYS`
   - the picker panel must be centered with anchor-relative negative offsets
   - cards must have readable names/descriptions and visible hover states
   - add temporary diagnostics in `_show_options()` so headless runs can prove the picker opened

4. Safety:
   - no `.tscn` files may be reintroduced for gameplay scenes
   - keep `Main.tscn` minimal
   - do not use typed references that recreate parse-time cycles
   - document every fix in `CHANGELOG.md`

## Acceptance checks

Run locally and in CI:

```powershell
godot --headless --import
godot --headless --quit-after 60
```

Expected:

- exit code 0
- zero `SCRIPT ERROR`
- zero `Parse Error`
- zero `CrashHandlerException`
- log should include `[Wave] Started wave 1 with 3 enemies`
- when a level-up is forced, log should include an `[UpgradePicker]` diagnostic
